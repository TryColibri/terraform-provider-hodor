# Terraform provider for Hodor

The `hodor` provider manages a Hodor workspace's connectors,
groups and contracts through the Hodor public API
(`https://api.hodor.ai/v2`), with a workspace API key, which a workspace admin
makes in Settings > API keys.

Its documentation is what the Terraform Registry renders from [`docs/`](docs/index.md):
the provider block, one page per resource with an example, what it cannot do yet and
its import id, and the guide [Set up a workspace](docs/guides/bootstrap.md), every
resource in one configuration.

| Resource | Import id |
|---|---|
| `hodor_group` | `grp_8fK2mQ9xLr4T` |
| `hodor_group_membership` | `grp_8fK2mQ9xLr4T/alice@example.com` |
| `hodor_contract` | `ctr_Vb3nX7pQ2kLm` |
| `hodor_contract_version` | `ctr_Vb3nX7pQ2kLm/ctv_9TzR4wYc1HsE` |
| `hodor_connector` | `con_Q4mZ8sN2bV6p` |

An id is its resource's prefix and 12 letters and digits, which Hodor makes when the
resource is created (plan 39 D6); every argument and import id that takes one checks
that shape before any request.

Workspace policies are not in the provider yet: they come back once the public API
has them again.

Three data sources: `hodor_workspace` reads the provider's workspace,
`hodor_integration` an entry of its catalog by id, slug or name, whose `id` a
connector names and whose `tools` a permission set
takes as they are, and `hodor_permission_set` builds a contract version's permission
set in the configuration, with no request.

## Source and releases

The provider is developed in Hodor's private monorepo and published to the public
repository [TryColibri/terraform-provider-hodor](https://github.com/TryColibri/terraform-provider-hodor),
one commit per release, tagged `vX.Y.Z`, from which the Terraform Registry publishes it.
A pull request opened on the public repository is ported to the monorepo by hand.

## Develop

Go, at the version `go.mod` names. The folder is a Go module of its own and builds
alone:

```sh
go build ./... && go vet ./... && go test ./...
```

| Path | Holds |
|---|---|
| `main.go` | the plugin server, at `registry.terraform.io/trycolibri/hodor` |
| `internal/hodorapi/` | `public.json`, a copy of the public API's spec, and the client oapi-codegen generates from it (`go generate ./...`). Never edited by hand |
| `internal/client/` | the client the resources call: the workspace API key as a bearer token, a `429` retried after its `Retry-After`, the `Deprecation` and `Sunset` headers recorded, Problem errors |
| `internal/provider/` | the provider block, and one resource per `<name>_resource.go` with its tests, listed in `resources.go` |
| `docs/` | the Registry docs, generated by tfplugindocs (`go generate ./...`, Terraform on the `PATH`) from the schema's descriptions, `templates/` and `examples/`. Never edited by hand |
| `templates/` | one page per resource, `resources/<name>.md.tmpl` (`group`, not `hodor_group`), the provider's `index.md.tmpl` and the guides: the prose around the generated schema, a resource's limitations among it |
| `examples/` | `provider/provider.tf`; per resource `resources/<type>/resource.tf`, `import.sh` and `import-by-string-id.tf`; the guide's `bootstrap/main.tf` |
| `.goreleaser.yml`, `terraform-registry-manifest.json`, `LICENSE` | the release: GoReleaser builds every platform's zip, the checksums signed with the namespace's GPG key and the manifest (plugin protocol 6) the Registry reads |
| `release/` | in the monorepo only: the allowlist of files the public repository gets (`release/mirror.go`), the version check and the pinned GoReleaser, run by the monorepo's release workflow (`go run ./release`) |

The provider calls only what the spec declares. When the spec changes, copy it into
`internal/hodorapi/` and run `go generate ./...`.

A new resource adds its example and both import files under `examples/resources/`, and
usually its template under `templates/resources/`; a changed description, template or
example is followed by `go generate ./...`. `docs_test.go` fails when `docs/` is not
what that generates, when a resource has no example or import id, when an attribute
has no Markdown description or a resource's argument does not say what changing it
does (in place, a replacement, a new version), and when an example
is not valid Terraform for the provider as built (`terraform validate` against this
build, nothing downloaded); without Terraform on the `PATH` it skips, except in CI.
Every example also runs: `TestAccExamples` (`internal/provider/acceptance_examples_test.go`)
applies each one on the test stack, and a new example gets its line there.

`go test ./...` skips the acceptance tests (`TestAcc*`). They run Terraform against a
Hodor stack built from source, each test in a workspace of its own, with `TF_ACC=1`,
`HODOR_ENDPOINT` (the stack's public API host) and `HODOR_ACC_SEED` (the command that
seeds a workspace there); `internal/provider/acceptance_test.go` says how, and how a
resource adds its own.
