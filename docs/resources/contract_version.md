# hodor_contract_version (Resource)

One version of a contract: its complete configuration, the tools it opens on each connector, the groups it serves and Code Mode. A version is immutable: changing any attribute creates a new version in place of this one, and destroying it only removes it from the state, since Hodor keeps every version. The contract's latest version is the one in force while the contract is on: creating a version puts it in force at once, or, while the contract is off (`hodor_contract`'s `enabled`), stores it until the contract is switched on. Declare one per contract. To roll back, restore the older configuration and apply: a new version, under a new number. Import it by its contract's id and its id, `ctr_.../ctv_...`; importing a version puts nothing in force.

## Example Usage

```terraform
# The Notion entry of the workspace's catalog: its tools, by name.
data "hodor_integration" "notion" {
  slug = "notion"
}

# Without a key it is installed but cannot call Notion: give it one with
# api_key_wo, as hodor_connector's example does.
resource "hodor_connector" "notion" {
  integration = data.hodor_integration.notion.id
  scope       = "shared"
  name        = "Notion"
}

resource "hodor_group" "support" {
  name = "Support"
}

resource "hodor_contract" "support" {
  name = "Support"
}

# In force once applied while the contract is on: the contract's latest
# version is the one in force. A version is immutable: changing any of this
# creates a new version, in force at once while the contract is on.
resource "hodor_contract_version" "support" {
  contract_id = hodor_contract.support.id

  permission_sets = [
    {
      connector_id = hodor_connector.notion.id
      # Every Notion tool, each named in the plan; list names to grant fewer.
      tools = data.hodor_integration.notion.tools
    },
  ]
  group_ids = [hodor_group.support.id]
}
```

## Limitations

- The contract's latest version is the one in force while the contract is on (`hodor_contract`'s `enabled`): a version is in force once applied. A version created while the contract is off is stored, and goes in force when the contract is switched on. A contract with no version grants nothing. Declare one `hodor_contract_version` per contract: two would fight for the latest.
- A version is never edited: any change plans a replacement. Terraform removes the old version from the state, then creates the new one, which is in force at once while the contract is on; the old one stays in force until then.
- Roll back by restoring the older configuration and applying: Hodor creates a new version with it, under a new number, in force at once while the contract is on, or once it is switched on. Importing an older version puts nothing in force.
- Destroying a version only removes it from the state. Hodor keeps every version of a contract until the contract is deleted.
- A tool is named as its connector's integration lists it, and resolved to that tool when the version is created. A tool renamed upstream later reads under its new name, which Terraform plans as a new version.
- A permission set lists its tools: there is no "all tools", so a tool the connector gains later is not enabled until a new version lists it.
- `code_mode = true` needs Code Mode on for the workspace: without it the API answers `403 feature-disabled`.
- Workspace policies are not in the provider yet: they come with a later release. A version keeps the policies its contract's latest version attaches, as set in the Hodor app.

## Schema

### Required

- `contract_id` (String) The contract's id, `ctr_...`, e.g. `hodor_contract.x.id`. Changing it creates a new version.

### Optional

- `code_mode` (Boolean) Whether the version's agents get Code Mode (search and execute) instead of its tool list. Turning it on needs Code Mode on for the workspace. Defaults to `false`. Changing it creates a new version.
- `group_ids` (Set of String) The groups the version serves, `grp_...`, e.g. `hodor_group.x.id`. Left out, none. Changing it creates a new version.
- `permission_sets` (Attributes Set) What the version opens on each connector, one permission set per connector, in any order. Each can be written in place or taken from `data.hodor_permission_set.x.value`. Left out, none: the version grants no tool. Changing it creates a new version. (see [below for nested schema](#nestedatt--permission_sets))

### Read-Only

- `id` (String) The version's id, `ctv_...`.
- `number` (Number) The version's number in its contract: 1, 2, 3...

## Import

A version is imported by its contract's id and its id, joined by `/`: `<contract id>/<version id>`, each its prefix (`ctr_`, `ctv_`) followed by 12 letters and digits, as Hodor answered them. The latest version's id is `GET /v2/workspaces/{workspace_id}/contracts/{contract_id}/versions/current`'s `id`.

In Terraform 1.5 and later, with an [`import` block](https://developer.hashicorp.com/terraform/language/import):

```terraform
import {
  to = hodor_contract_version.support
  id = "ctr_Vb3nX7pQ2kLm/ctv_9TzR4wYc1HsE"
}
```

Or with the [`terraform import` command](https://developer.hashicorp.com/terraform/cli/commands/import):

```shell
terraform import hodor_contract_version.support ctr_Vb3nX7pQ2kLm/ctv_9TzR4wYc1HsE
```
