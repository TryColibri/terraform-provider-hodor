# hodor_connector (Resource)

A connector of the workspace: an integration its catalog already holds, installed in one scope under one name, which contracts grant tools of. Removing it removes every connection of it and its place in every contract. A new integration is added to the catalog in the app, and an OAuth connector is connected there. Import it by its id, `con_...`.

## Example Usage

```terraform
# The API key the connector calls Notion with. Ephemeral: Terraform keeps it
# out of plan and state files.
variable "notion_api_key" {
  type      = string
  sensitive = true
  ephemeral = true
}

# The Notion entry of the workspace's catalog: a connector names it by its id.
data "hodor_integration" "notion" {
  slug = "notion"
}

resource "hodor_connector" "notion" {
  integration = data.hodor_integration.notion.id
  scope       = "shared"
  name        = "Notion"

  # Sent on create and again whenever the version changes: bump it when the
  # key rotates.
  api_key_wo         = var.notion_api_key
  api_key_wo_version = 1
}
```

## Limitations

- Replacing the only connector of an integration the workspace made itself (a custom MCP or OpenAPI connector) fails: Terraform deletes the connector first, which removes the integration with it, and the create then finds no integration. Keep another connector of that integration while changing `integration` or `scope`, or add the new connector under another name before removing the old one.
- Hodor does not say whether a connector holds a key. A key removed in the app stays removed until `api_key_wo_version` changes; removing `api_key_wo` and `api_key_wo_version` from the configuration leaves the key in place.
- A new integration is added to the workspace's catalog in the Hodor app, and a personal or OAuth connector is connected there.

## Schema

### Required

- `integration` (String) The id of the integration the connector installs, `int_...`, from the workspace's catalog: `data.hodor_integration.x.id`. Changing it replaces the connector.
- `name` (String) The connector's name in the workspace, unique there: letters and digits, with single `_` between them, 32 characters at most. Its tools are named after it, so an integration with long tool names allows fewer: the API's error says how many. Changing it renames the connector in place.
- `scope` (String) Whose connection it holds: `shared`, one connection the whole workspace shares, or `personal`, each member's own, made in the app. Changing it replaces the connector.

### Optional

> **NOTE**: [Write-only arguments](https://developer.hashicorp.com/terraform/language/resources/ephemeral#write-only-arguments) are supported in Terraform 1.11 and later.

- `api_key_wo` (String, Sensitive, [Write-only](https://developer.hashicorp.com/terraform/language/resources/ephemeral#write-only-arguments)) The API key a shared connector calls its provider with, as the provider issued it; `user:password` for one that signs in with basic auth. Write-only (Terraform 1.11 or later): never stored in the state nor shown in a plan. It is sent when the connector is created and whenever `api_key_wo_version` changes, checked with the provider first when the provider has a check. Only a shared connector of a provider that takes a key has one: a personal or an OAuth connector is connected in the app. Removing it with its version leaves the connector's key as it is. Set and removed together with `api_key_wo_version`: one without the other fails validation. Changing it alone sends nothing; it never replaces the connector.
- `api_key_wo_version` (Number) Set and removed together with `api_key_wo`: one without the other fails validation. Change it to send `api_key_wo` again, e.g. after rotating the key. Any change counts, up or down, and is made in place: it never replaces the connector.

### Read-Only

- `id` (String) The connector's id, `con_...`.

## Import

A connector is imported by its id, `con_` followed by 12 letters and digits, as Hodor answered it when the connector was created: the `id` of the `hodor_connector` in another state, for example. The Hodor app does not show it yet. The API key is never read back: set `api_key_wo` and a new `api_key_wo_version` to send it again.

In Terraform 1.5 and later, with an [`import` block](https://developer.hashicorp.com/terraform/language/import):

```terraform
import {
  to = hodor_connector.notion
  id = "con_Q4mZ8sN2bV6p"
}
```

Or with the [`terraform import` command](https://developer.hashicorp.com/terraform/cli/commands/import):

```shell
terraform import hodor_connector.notion con_Q4mZ8sN2bV6p
```
